# Quickstart — build, prove, verify, and reuse the tech

This repo is a **general-purpose transparent-STARK verification stack** (no trusted
setup) that happens to settle a game. The field, transcript, Merkle, FRI, codec,
Poseidon2 and ProofRegistry layers are game-agnostic — only one contract (the
constraint evaluator) is generated per program. See `AUDIT.md` for the security
model and `DEPLOYMENTS.md` for the live testnet addresses.

## 1. How it's built (technical)

**Prover (`zk/stark`, Rust, Plonky3 0.6.3).** Each program is an AIR — a table with
one row per computation step and columns for state + range-check bits + embedded
Poseidon2 permutations. The round AIR (`src/round.rs`) proves the engine's fixed-point
price recurrence AND binds all randomness (noise, jumps, regime Markov chain) to a
**seed committed before the round** via Poseidon2, and order flow to `orderLogHash`.
The batch AIR (`src/batch.rs`) chains N rounds with a gated Poseidon2 **boundary
sponge** so one proof covers N rounds. Proofs use a **keccak256** StarkConfig
(`config::make_keccak_config`) — keccak MMCS + a serializing challenger — because
keccak is a native EVM opcode and Poseidon2 verification would be gas-prohibitive.

**Verifier (`contracts/verifier`, Solidity).** Game-agnostic layers: `GoldilocksField`
(base + degree-2 extension), `KeccakTranscript` (Fiat-Shamir, byte-for-byte match to
p3), `MerkleVerifier`, `FriFolding`/`FriVerifier`/`FriDeep` (FRI + DEEP openings),
`ConstraintEval` (Lagrange selectors + quotient recomposition), `StarkProofCodec`
(parses calldata, range-checks every element `< p`), and `StarkVerifier.verifyOpenings`.
The **per-AIR** piece — `RoundConstraints.sol` / `BatchConstraints.sol` — is
auto-generated by `zk/stark/src/bin/codegen_air.rs` and split across many
sub-contracts to stay under the 24KB EIP-170 limit (compact SSA over a flat
`uint256[]`, ~16 bytes/node, with a two-level dispatcher).

**On-chain Poseidon2** (`Poseidon2Goldilocks.sol`) matches p3 byte-for-byte, used by
the batch path to recompute `batchCommit`. **`ProofRegistry.sol`** stores a proof in
≤24KB SSTORE2 chunks so a proof larger than the ~128KB per-tx calldata limit is
verified via an internal call (no transaction ever carries the whole proof).

## 2. Reuse it for another provably-fair game

Everything except the constraint evaluator is reusable verbatim. To ship a new
provably-fair game (dice, crash, plinko, a different market, …):

1. Write your engine's AIR in Rust (model on `zk/stark/src/round.rs`): bind your
   randomness to a committed seed (Poseidon2 counter mode) and your inputs to a
   commitment; expose your public values.
2. Generate its Solidity evaluator:
   `cargo run --release --bin codegen_air -- <yourair>` → `YourConstraints.sol`.
3. Deploy a verifier entry that calls `StarkVerifier.verifyOpenings` + your
   `YourConstraints.foldConstraints` (copy `RoundVerifierEntry.sol`).
4. Point your settlement/app contract at it. The field, transcript, Merkle, FRI,
   codec, Poseidon2 and ProofRegistry are unchanged.

The result: a trustless, no-ceremony proof that your game ran correctly, verifiable
by anyone on-chain.

## 3. Build, prove, verify (local)

```bash
# prover + AIRs
cd zk/stark && cargo test --release          # all AIRs prove + verify
cargo run --release --bin generate_round_stark   # emits PROOFBYTES (a real proof)

# Solidity verifier + settlement + battle-test suite
cd ../.. && forge test                        # 99 tests, differential vs the prover
```

## 4. Redeploy on your own chain

```bash
export RPC_URL=<your evm rpc>
export DEPLOYER_KEY=<funded deployer key>      # never commit this

# optimistic stack (verifier + settlement + positions); ~180 contracts, use --slow
forge script script/DeployOptimistic.s.sol \
  --rpc-url $RPC_URL --private-key $DEPLOYER_KEY --broadcast --slow

# batch (eager) stack
forge script script/DeployBatchStack.s.sol \
  --rpc-url $RPC_URL --private-key $DEPLOYER_KEY --broadcast --slow

# ProofRegistry (for proofs over the ~128KB tx-calldata limit)
forge script script/DeployRegistry.s.sol \
  --rpc-url $RPC_URL --private-key $DEPLOYER_KEY --broadcast --slow

# verify a real proof on-chain (read-only)
forge script script/VerifyLive.s.sol --rpc-url $RPC_URL
```

Then wire the FarmPool operator to `RollaPositions`, and (optionally)
`settlement.setRegistry(proofRegistry)` to enable large-proof disputes.

## 5. Benchmarks (Robinhood testnet 46630)

Single-tx latency ~1.3s, ~15 tx/s burst per account, sub-second blocks. Per-op gas:
pool deposit 41k, withdraw 47k, add-liquidity 45k. On-chain STARK verify (dispute /
batch) ~600–800M gas — dispute-only under optimistic settlement. Full table in the
README; verifier gas is dominated by the DEEP opening over the trace width and scales
with FRI `num_queries` (raise to ~80–100 for production security).
